## 매칭과 채팅

- 철자 유사도 기준값(0.2, 1위 대비 0.5)은 시드 부품으로 정한 임시값이다. "베아링" 같은 오타에서 "오링"이 함께 후보에 오른다. F-SIM 합성 데이터로 조정이 필요하다.
- 명세의 확정 조건에 맞춰 이름만 비슷한 후보는 하나여도 선택 카드를 띄운다. 현장 입력 횟수가 늘 수 있어 임베딩 도입 후 코사인 확정 조건(0.85, 차이 0.05)과 함께 다시 본다.
- 매칭은 회사의 모든 부품·별칭을 읽어 Python에서 점수를 낸다. 부품 1,000종에서 채팅 응답 3초 기준을 넘는지 측정해야 한다.
- 규격 추출 정규식은 시드 카테고리(베어링, 볼트, V벨트, 오링, 용량)만 다룬다. 카테고리가 늘면 패턴을 추가해야 한다.

## 데이터·환경

- 이름 정렬은 `COLLATE "C"`로 고정했다. 앞으로 문자열 정렬·커서가 들어가는 API도 같은 원칙을 따라야 로케일마다 결과가 달라지지 않는다.
- 로컬 테스트 클러스터는 PostgreSQL 15, CI·compose는 16이다. 버전 차이로 생기는 문제(예: `lc_collate` 설정 제거)는 CI에서만 잡힌다.
- 외부 지표 시드 CSV는 2026-11-02까지의 값이다. 시간이 지나면 `stale`이 되고 위험도가 실제와 달라진다. 실제 출처(API 명세서 15장 보류 항목)가 정해지면 교체한다.

## 보안·운영

- DEV-03 시드 초기화는 모든 회사의 데이터를 지운다. `APP_ENV=dev`에서만 라우트가 생기지만, 공유 개발 서버에서는 주의가 필요하다.
- 이름 목록 호출 제한은 `request.client.host` 기준이다. 프록시 뒤에 두면 `X-Forwarded-For` 처리가 필요하다.
- `rate_limits` 테이블을 비우는 배치가 없다. 오래된 창 기록이 계속 쌓인다.
- 리프레시 토큰은 갱신해도 이전 토큰을 폐기하지 않는다(명세에 규정 없음). 탈취 대응이 필요하면 재사용 감지를 더한다.
- 스케줄러 작업 목록은 메모리에만 두어, 꺼져 있던 동안 놓친 실행은 다시 하지 않는다. 필요하면 DEV-01이나 CLI로 수동 실행한다.
