### 명세 동기화

- Notion 기능명세서·API 명세서에 구현과 다르게 정한 것과 정의가 없던 기준을 반영했다(A1~A19, C1~C2). 검토 기록은 Notion「발주콕 명세 ↔ 구현 차이 수정안」 페이지.
- 저장소 기준 API 문서는 `docs/api-spec`에 기능별로 정리했다.

## 결정과 근거

- 회사 격리는 `FORCE ROW LEVEL SECURITY` 대신 소유자가 아닌 전용 역할(`bjk_app`)로 한다. 로그인 전 조회 함수가 막히지 않고 앱이 RLS를 끌 권한이 없다(기능명세서 F-AUTH-04 수정 반영)
- 비밀번호·PIN 해시는 argon2id (F-AUTH-01·02 수정 반영)
- 배치 예약은 API와 분리한 APScheduler 프로세스, 실행·잠금·기록은 공통 `run_job` (2장 기술 스택, 17장 compose 한 번 실행)
- 문자열 정렬은 DB 로케일과 무관하게 `COLLATE "C"`, 테스트 DB는 운영과 같은 `en_US.UTF-8`
- ai 파트(#20·#21)는 진행하지 않고 server에 해석 포트와 폼 입력 대체 경로만 둠 (사용자 지시)

## 검증

- 로컬: PostgreSQL 15 클러스터 두 개(C 로케일, en_US 로케일)에서 `REQUIRE_DB_TESTS=1 make test` 230개 통과, `make lint` 통과.
- CI: PostgreSQL 16 서비스로 DB 테스트까지 실행, 스택 PR 26개 통과. `image build`로 server·ai Dockerfile 빌드 확인.
- 스케줄러는 실제 프로세스를 앱 계정으로 띄워 기동과 SIGTERM 종료를 확인했다.
