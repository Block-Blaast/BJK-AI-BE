## 결정과 근거

- **형식 공용화:** ai 의견서와 양식 의견서가 같은 구성이어야 같은 검증(체크 근거 줄 수 등)을 통과함. 표시 이름은 API 명세서 2장 코드값 사전이라 `bjk_contracts`에 둠
- **허용 목록:** 의견서 요청에 있는 숫자(체크 근거, 원안·수정안·대안 수량·단가·총액·절감액, 예상 손실)와 날짜(근거 날짜, 소진 예상일, 계산 시각) + 파생값(단가 차액, 수량 차, 재고 합계, 숨은 재고 합계, 평균 대비 비율) + 기준 설명용 95%·99%
- **정규화:** 쉼표, 만·천·억(예: "1만 8천원" → 18000), %, "11월 8일"·"2026-11-08"·"2026년 11월 30일" 날짜, "03:00" 시각
- **오차:** 금액(원·만·천)은 천 원 미만 차이, 비율은 1%p, 소수는 쓴 자릿수로 반올림해 비교
- **이름 속 숫자는 제외:** 부품명(6205ZZ, M8×20), 공급사명, 설비명(3호기), 연휴명은 지운 뒤 검사
- **판정 일치:** 첫 줄 머리가 실제 판정·표시와 같고, 본문에 다른 판정 표시(`[적정` 등)가 없을 것
- **누락:** 체크 근거 줄 수 = 걸린 체크 수, 체크마다 이름 또는 관련 낱말이 있을 것. 문장 뜻을 이해하는 검사는 아님
- **재작성 흐름:** 첫 작성 + 재작성 2회 = 최대 3번 ai 호출. 검증 오류 문자열을 그대로 `feedback`으로 넘김. ai가 대체 응답(`text: null`)이나 None이면 바로 양식
- **양식 의견서도 검증:** 입력값만 쓰지만 `verified`는 실제 검증 결과로 채움. 예시 6건 모두 통과를 테스트로 고정
- **`write` 콜백은 동기 함수:** server의 ai 호출을 주입받음. 실패 시 예외 대신 None을 돌려주는 계약

## 검증

- `uv run pytest`: 87개 통과(검토 52개). `bjk_review` 커버리지 97%
- `ruff check`, `ruff format --check` 통과
- **실제 Gemini 끝까지 실행(예시 6건, 판정 → 의견서 요청 → `/v1/opinions` → 검증):**
  - 1차: 4건 첫 시도 통과, 6205는 C-09 문장("납기 위험 주의")을 누락으로 판정해 재작성 2회 후 양식 대체, 볼트 H_u는 C-07 누락으로 1회 재작성 후 통과
  - 원인: 언급 판단 낱말이 좁았음. C-07·C-08·C-09 낱말을 넓히고 프롬프트에 체크 이름을 드러내라고 추가
  - 2차: 6건 모두 첫 시도 통과(`source: llm`, `verified: true`), 건당 1.0~1.9초
  - 실제 Gemini 의견서 하나(V벨트)를 테스트(`GEMINI_VBELT`)에 고정
- **검증의 한계(확인됨):** 1차 볼트 H_u 의견서에서 요청 수량 50개를 "다른 열린 요청 50개"로 잘못 부름. 숫자 자체는 허용 목록에 있어 통과함. 숫자 검증은 "어떤 숫자를 무엇이라고 불렀는지"까지는 보지 못함. 프롬프트에 기호 혼동 금지를 추가함
- 루프가 바뀔 때 이전 Gemini 클라이언트 정리 경고 로그는 여전히 남음(결과 영향 없음, uvicorn에서는 발생 안 함)
