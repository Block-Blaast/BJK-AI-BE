## 결정과 근거

- 사용자 결정: 서버가 목업을 가져가고, 실제 DB에 더미 데이터를 넣어 나중에 서버에서 실제 결과를 추가
- 범위는 검증 리포트만. 디지털 트윈·채팅 inbox·채팅 재고 부족 초안은 계약부터 정해야 해 제외
- 응답은 프론트 목업 배열 대신 공통 커서 목록(`items`). 프론트 타입은 `/v1` 경로로 옮길 때 맞춤
- 더미 행에 결과 수치·PDF는 넣지 않음. F-SIM의 "실제 실행한 값만" 규칙을 지키고 `source: sample`로 구분
- PDF 경로 컬럼은 두지 않음. PDF를 만드는 하네스와 함께 정함

## 남은 일·확인 필요

- F-SIM 검증 하네스(합성 데이터, 시나리오 주입, 평가, 정책 재생)와 리포트 PDF
- Notion API 명세서 반영 여부
- 프론트 `simReports` 경로를 `/v1/sim-reports`로 바꾸고 `items`를 읽도록 수정
