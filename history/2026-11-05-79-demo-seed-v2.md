# 시연 시드 확장 demo_v2

- 날짜: 2026-11-05
- 영역: server(시드), 사용자 요청
- 관련: #285, DEV-03, F-ANAL, F-AUDIT-05·06, F-REVIEW

## 목적

- 운영 시연 DB가 demo_v1(부품 6종·이력 12주)뿐이라 검토 근거가 0이거나 화면이 대부분 비어 있음
- 프론트 가상 공장 목업 데이터를 실제 DB로 옮겨 시계열·공급사·설비가 풍부한 시연 상태를 만듦

## 한 일

- `seed/data/demo_v2.json`: 프론트 `mocks/fixtures`(2026-11-05)에서 부품 100종(demo_v1 6종과 겹치는 부품 제외), 공급사 7곳, 설비 6대, 정비 3건, 선반 8개 배치를 옮김
- `seed/demo_v2.py`: demo_v1을 그대로 만든 뒤 카테고리 4개(씰·오링, 공압·유압, 절삭공구, 필터)·대체 공급사 단가·설비 3대 추가, demo_v1 설비 이름을 가상 공장 이름으로 바꾸고 3D 배치를 선반 8개·부품 106종으로 교체
- 부품마다 52주 출고(패턴별 빈도·변동, 계절성)와 재주문점 발주·입고를 고정 난수로 시뮬레이션. 입고는 발주와 원장(`po_id`)으로 연결, 단가는 수입 의존 카테고리에 1년 상승분, 20%는 대체 공급사 발주
- 마지막 재고가 목업 재고와 같도록 시작 재고를 맞추고, 남는 차이는 어제 정기 실사 조정 한 건으로 메움
- 지난 정기 실사 기록(닫힌 실사 기한 항목 + 차이 없는 실사 요청)을 90% 부품에 넣음. 나머지는 실사 기한 지남 시연용
- 시드 CLI `--scenario demo_v2`: 시드 뒤 nightly·weekly-merge·missed-scan·briefing과 예시 직원 요청 5건 검토를 앱 계정으로 실행
- DEV-03 `scenario`에 `demo_v2` 허용(시드만, 배치는 돌리지 않음), 명세 `docs/api-spec/dev.md` 갱신
- 테스트 `test_seed_v2.py` 8개

## 결정과 근거

- demo_v1을 고치지 않고 새 시나리오로 둠. 79개 테스트 파일이 demo_v1 값에 기대고 있어서
- demo_v2도 demo_v1 ID 규칙을 씀. 운영 프론트가 기기에 저장한 시연 계정 토큰이 재시드 뒤에도 그대로 쓰이게 하기 위해
- 근거 지표·검토는 시드가 직접 쓰지 않고 실제 배치·검토 엔진으로 만듦. 화면 숫자가 실제 계산과 같아야 해서
- 입고 시각은 08시로 둠. 같은 날 출고보다 늦으면 원장 중간 재고가 0 밑으로 가 음수 재고 항목이 생겼음

## 검증

- 로컬 PostgreSQL에서 `python -m bjk_server.seed --scenario demo_v2`(외부 수집 끔, ai 없음): 부품 106, 원장 약 3,300건, 발주 약 590건, 근거 지표 106, 병합 후보 10, 놓친 발주 초안 3, 예시 요청 5건(적정·수정 권고·보류), 실사 기한 지남 13건, 약 4초
- `test_seed_v2.py`·`test_seed.py` 16개 통과(DB 포함)
- 전체 `REQUIRE_DB_TESTS=1 uv run pytest`: 964개 통과, 1개 건너뜀(로컬 PostgreSQL)

## 남은 일·확인 필요
